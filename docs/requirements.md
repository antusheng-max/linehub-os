# 需求说明

## 1. 产品范围

LineHub OS 面向 x86_64 OpenWrt 软路由，管理一条或多条以 PPPoE 接入的 WAN，并提供多 VLAN、多拨和 IPv4/IPv6 双栈下的可靠分流能力。第一阶段交付规划、UCI 模型、包边界和测试骨架，不制作固件或实施真实网络配置。

## 2. 功能需求

1. **线路接入：** 支持物理接口、802.1Q VLAN、每 VLAN 多 PPPoE，以及单 VLAN 多 PPPoE 会话。
2. **会话隔离：** 每个 PPPoE 会话可设置独立的本地管理 MAC、IPv4/IPv6 开关、权重和健康检查引用。
3. **线路池：** 可将可用 WAN 组织进池，由权重选择新流；失效线路自动从候选集中移除，恢复后按策略加入。
4. **双栈：** IPv4 和 IPv6 独立探测、标记、路由表和故障状态。IPv6 委派前缀逐 WAN 保存与发布。
5. **连接一致性：** 首包选 WAN 并记录连接标记；同一 TCP 或 UDP 连接的后续包必须走同一 WAN。
6. **策略：** 能按源网段、目的前缀、协议、端口、DSCP 和线路池表达规则，优先级明确且可审计。
7. **管理：** LuCI 应展示拓扑、会话、地址族、健康结果和策略生效状态；批量变更通过受控 UCI 事务提交。
8. **诊断：** 提供只读状态快照和配置一致性检查，不暴露凭据。

## 3. 约束和非功能需求

- 依赖 OpenWrt 的 Linux 内核/驱动、netifd、pppd、odhcp6c、UCI、ubus、rpcd 与 nftables；LineHub 不重新实现这些组件。
- 凭据不得出现在日志、诊断 API、浏览器回显或版本库。示例仅使用虚构值。
- 配置应用必须可校验、幂等并支持失败回滚设计。
- 普通多 WAN 是流量分担，不是单 TCP/UDP 流的带宽叠加。
- 多个公网 IPv6 委派前缀保持独立；不把它们宣称为一个真正合并的公网前缀。
