# 网络模型

## 拓扑

`device` 描述物理父接口；`vlan` 在父接口上创建逻辑承载；一个 `pppoe` 段引用一个 VLAN。多个 PPPoE 段可引用同一 VLAN（单 VLAN 多拨），也可以分布在多个 VLAN（多 VLAN 多拨）。每段有唯一 `wan_id`，并可指定独立、本地管理的 MAC 地址。

LAN 段定义固定 IPv4 管理地址和 RFC 4193 ULA 前缀。文档测试中的 IPv4 使用 192.0.2.0/24、198.51.100.0/24、203.0.113.0/24；IPv6 文档地址使用 2001:db8::/32，绝不代表真实运营商地址。

## 流选择与粘性

1. 新建连接先按地址族筛选健康、启用且属于目标池的 WAN。
2. 依据策略匹配结果和权重选择一个 `wan_id`，并为连接写入稳定 mark。
3. 所有属于该 conntrack 条目的 TCP 或 UDP 报文恢复相同 mark，再进入对应 WAN 的路由表。
4. 已建立流不因为权重变化漂移。线路失效时，仅新流改选；既有流的异常由协议重传/重新建连处理。

因此，普通多 WAN 只能把多个连接分散到多条 WAN，不能把单个 TCP（或 UDP）连接的带宽叠加起来。需要单流加速时，必须采用端到端支持的其他技术，且不属于本项目第一版。

## IPv6 原则

IPv6 DHCPv6-PD 与路由状态按 PPPoE 会话独立采集。LAN 可以拥有来自不同 WAN 的多个可路由前缀和 ULA，但每个公网前缀的来源、寿命与出口线路必须可追溯。它们是多个独立的公网前缀，**不是真正合并为一个公网前缀**。出站 IPv6 流同样按连接固定出口；入站和源地址选择必须保证回程可达并避免前缀泄漏。
